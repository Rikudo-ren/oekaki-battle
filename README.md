# おえかきバトル！

友だちと同じ部屋に集まり、順番に絵を描いて当てるオンラインゲームです。2〜8人で遊べます。ホストが正解枠などを設定して開始すると、描く順番がランダムに決まります。

- 各ターンは **3・2・1のカウントダウン**のあとにスタート。描く人だけにお題が表示され、ほかの人には文字数が表示されます。答えはチャットにひらがな（長音「ー」を含む）で、お題と同じ呼び方を入力します。PCではゲーム中、チャット欄をクリックしなくても文字入力を始められます。スマホはキーボードを出すために入力欄をタップしてください。言い換えは正解になりません。
- 複数人が正解できる設定では、正解者の名前を画面に通知します。お題が切り替わるとチャット入力欄の未送信文字は消えます。
- チャット送信時は安全確認をカウントダウン中に行い、回答確認とメッセージ送信を並行して待ち時間を減らします。送信中は本人に「送信中…」と表示し、通信状況によって実際の反映時間は変わります。最新のRealtime Databaseルールの公開が必要です。
- チャットに入力した正解は発表まで伏字で保存・表示し、発表後に答えを表示します。描き手は普通の会話はできますが、お題と完全に一致する投稿はできません。文章に答えを含めたり別表記を使った場合までは防げません。
- BGMと効果音は初期状態ではオフです。画面上部のボタンでそれぞれオンにでき、設定は同じブラウザに保存されます。
- 正解枠がすべて埋まると、ホイッスルと画面全体の「終了！」で知らせ、約2秒後に答えを表示します（効果音はミュート可能）。
- GMが退出ボタンから退出すると部屋は解散し、全員がホームに戻ります。GM以外は、部屋が残っていれば切断・退出後に同じブラウザから合言葉で戻れます。進行中も8人以内なら新しい人が参加でき、進行中のターンに空き枠があれば回答できます。途中参加者の描画ターンは、すでに決まっていたその周の描画順の後ろに追加します。開始時刻や進行済みターンは変更しません。正解枠の人数はターン開始時に確定し、途中参加者を含む人数は次のターンから反映されます。個室のゲーム終了後は既存参加者のみ再入室できます。公開部屋は終了後も新しい人が参加できます。
- 周回数の指定はなく、各ターンの答え発表後は自動で次のターンへ進みます。一周が終わるとGMが「次の周へすすむ」か「ゲームを終了してランキングを見る」を選びます。終了を選んだ場合だけ順位を確定して最終ランキングを表示します。接続中が1人以下になった場合はその時点で終了します。終了後は「ロビーに戻る」で設定画面に戻れます。新しい試合では得点はリセットされます。
- 正解できる人数は1〜7人、または「全員」（出題者を除く）から選べます。指定人数が回答者数を超える場合は回答者数に合わせます。正解してもすぐには終わらず、枠が埋まる・制限時間が切れる・ホストがホイッスルを鳴らすと「終了！」と表示し、約2秒後に答えと獲得点を発表し、自動で次に進みます。順位発表は試合終了時のみです。
- 制限時間は初期設定が30秒で、なし・30・60・90・120秒、または自由設定（10〜600秒）から選べます。時間ありでは正解した**各自の回答時刻**に応じ、最初・中間・最後の各3分の1で、答えた人に20・10・5点、描いた人に15・7・3点が入ります（初期設定）。描いた人には正解者1人ごとに加点され、順位による追加点はありません。各配点は0〜100点で変更できます。時間なしは答えた人1点・描いた人0点が初期設定で、それぞれ変更できます。
- お題は2〜6文字。時間ありの場合、文字ヒントを「なし・残り5・10・15・20秒」から選べます。2〜4文字なら1文字、5〜6文字なら2文字をランダムな位置に表示します。時間なしではヒントはありません。
- 描く番は「あなたが描く番！」と表示し、キャンバス周囲を暖色に切り替えます。答える番と正解済みの状態も表示します。描く人の番だけキャンバスを広くし、得点・残り時間・配点帯とチャットは表示したままにします。描いている途中の線も短い間隔でまとめて他の人に共有します。通信状況により遅れる場合があります。「消」の消しゴムは線を部分的に消せます。ペン太さと消し太さの設定は常に表示され、それぞれ別に調整できます。パスは確認なしで実行します。「もどす」は消しゴムを含め一筆全体を戻し、「全部消す」も使えます。待機中からゲーム終了まで、部屋のメンバー同士でチャットできます（開始カウントダウンと答え発表待ちの間は一時停止）。プレイ画面はPCの見やすさを優先し、中央のキャンバス、参加者、描画ツールと下部の横長チャットを配置します。スマホでも一画面に収まるようにし、チャット履歴とゲーム設定は必要なときに開けます。画面が極端に低い場合やキーボード表示中は、操作を隠さないようスクロール可能になります。

## 公開構成と料金

画面の公開には **Vercel**、匿名認証とリアルタイムデータの保存・同期には **Firebase Authentication / Realtime Database** を使います。Firebase Hosting や Cloud Functions は使いません。任意のAI対戦では Vercel Functions をAPI中継に使います。Vercel Hobby と Firebase Spark の無料プランで始められますが、どちらも利用条件・無料枠に制限があり、無制限ではありません。利用状況や最新の条件は各サービスのコンソールで確認してください。

## 1. Firebase を準備する

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作成（または既存プロジェクトを選択）し、料金プランが Spark であることを確認します。
2. 「Authentication」→「Sign-in method」で **匿名** を有効にします。
3. 「Realtime Database」でデータベースを作成します。リージョンを選び、最初はロックモードで作成してください。次のコマンドでこのリポジトリのルールを適用します。既存の `.firebaserc` は別プロジェクトを指している場合があるので、必ず `--project` に自分のプロジェクト ID を指定してください。

```sh
npx firebase-tools login
npx firebase-tools deploy --only database --project あなたのFirebaseプロジェクトID
```

4. プロジェクト設定の「マイアプリ」でウェブアプリを登録し、表示される Firebase 設定を控えます。Realtime Database の URL はデータベース画面でも確認できます（ウェブアプリの設定に含まれない場合があります）。

## 2. Vercel に公開する

1. [Vercel](https://vercel.com/) でこの GitHub リポジトリをインポートします。リポジトリの `vercel.json` にビルド設定があるため、Framework Preset は Other のままで大丈夫です。
2. デプロイ前に Vercel の Environment Variables に以下を設定します。各値は Firebase コンソールのウェブアプリ設定から取得し、`FIREBASE_DATABASE_URL` には手順1で作成した Realtime Database の URL を入れてください。本番とプレビューの両方で遊ぶ場合は **Production と Preview** の両方に設定します。

| Vercel の環境変数 | Firebase の値 |
| --- | --- |
| `FIREBASE_API_KEY` | `apiKey` |
| `FIREBASE_AUTH_DOMAIN` | `authDomain` |
| `FIREBASE_DATABASE_URL` | `databaseURL` |
| `FIREBASE_PROJECT_ID` | `projectId` |
| `FIREBASE_APP_ID` | `appId` |

3. デプロイします。Vercel で環境変数が不足しているとビルドは失敗します。後から環境変数を変更した場合は再デプロイしてください。
4. Firebase Authentication の「Settings」→「Authorized domains」に、公開された Vercel のドメイン（例: `example.vercel.app`、スキームやパスは不要）を追加します。プレビュー URL を使う場合も、そのホスト名を追加してください。
5. Vercel の URL を友だちに共有します。別の参加者は別のブラウザまたはプライベートウィンドウを使用してください（匿名認証の ID はブラウザ内で共有されます）。

Firebase のウェブアプリ設定はブラウザに配信される**公開情報**であり、Vercel の環境変数に入れても秘密にはなりません。アクセス制御には Realtime Database のルールを使います。サービスアカウントの秘密鍵は設定しないでください。

## 開発・動作確認

Node.js 22 を使用してください。`npm run build` で環境変数から `public/firebase-config.js` を生成し、`src/app.js` を `public/app.js` にバンドルします。生成された設定ファイルは Git に含めません。ローカルでは5つの環境変数がすべて未設定なら空の設定を生成し、ひとり用CPU対戦を試せますが、オンライン対戦はできません。一部だけ指定した場合はエラーになります。

```sh
npm install
# 対戦を試す場合は上記の5つの環境変数をシェルで設定してから実行
npm run build
npm test
npm run dev # 静的画面と /api/ai を同じサーバーで提供
```

Realtime Database ルールの実行テストには Java 21 と Firebase CLI（`firebase-tools`）が必要です。エミュレータは初回に Firebase からダウンロードされます。以下は `demo-oekaki` のローカル専用データを使い、本番には接続しません。

```sh
npm install
npx firebase-tools emulators:exec --only database --project demo-oekaki "node --test tests/rules-emulator.cjs"
```

ローカルでもオンライン機能には Firebase の設定とデプロイ済みデータベースルールが必要です。ローカルのドメインが Authentication の承認済みドメインに含まれているかも確認してください。

## AI対戦（任意）

タイトルの「AIと対戦する」を開き、OpenAI・Google Gemini・Anthropic Claude から選択してAPIキーを入力します。「利用できるモデルを取得」で一覧からモデルを選ぶか、「モデルIDを直接入力」で指定して対戦を始めます。画像入力とテキスト出力に対応するモデルが必要です。モデル一覧はサービスが返す一覧を絞ったもので、すべてのモデルの画像入力・利用権限を保証するものではありません。対応状況は各サービスの説明を確認してください。

- APIキーが空なら従来どおりCPU3人です。キーがある場合はAIと1対1で対戦し、CPUや用意済みの絵は登場しません。AI対戦の初期制限時間は60秒です。AIはお題をもとに座標の線画を作り、他の人の絵を画像として見て最大2回推測します。正解そのものはAIの回答リクエストには送りません。生成画像専用モデルではなく、線画の座標を出力できる対話モデルが必要です。AIの画力・正解率は保証できません。
- キーは入力した画面のメモリにのみ置き、ブラウザ保存・Firebase・リポジトリには保存しません。モデル一覧の取得と対戦時にはHTTPSでこのサイトのVercel Functionを経由して、選択したAIサービスに送信します。サイト運営者と各AIサービスを信頼できる場合のみ使用してください。リロードすると入力し直しです。
- 外部AIにお題やキャンバス画像が送られ、サービスの利用規約・データ保持方針が適用されます。API利用料が発生する場合があります。キーの利用上限を設定し、共有端末では退出後にページを閉じてください。チャット本文は送信しません。
- AI対戦はひとり用だけです。無効なキー、利用枠不足、非対応モデル、通信失敗、描画応答の不正や時間超過では理由を画面に表示し、CPUは代行しません。描画失敗時はGM操作でターンを終了できます。正解が分からない場合はAIは無回答になることもあります。
- Gemini 3.8 Flashでは待ち時間を抑えるため思考レベルをlowにし、描画はJSON出力を要求します。思考トークンを含めて描画は最大8192、回答は最大2048出力トークンを設定しています（実際の使用量に応じて課金される場合があります）。
- エラーに表示されるHTTP番号はAIサービスまたは中継のものです。400はキー・モデル・リクエスト、401/403はキーまたは権限、404はモデル、429は利用枠、5xxはサービス側の障害などを確認してください。中継からの接続失敗や25秒のタイムアウトも区別して表示します。モデル一覧の取得成功は描画・画像入力の利用を保証しません。
- `npm run dev` ではローカルの `/api/ai` を利用できます。`npx serve public` のような静的サーバーだけではAI機能を利用できません。公開環境では同じパスに Vercel Function をデプロイします。

## 仕組みと運用上の注意

- タイトルの「ひとりでCPU対戦」は、3人のCPUとのローカル対戦です。CPUは用意済みの18種類の線画からお題を選んで順番に描き、回答は絵を認識せずタイミングを模擬します。人間が描くお題は通常と同じ候補から選ばれます。部屋・得点はブラウザ内の一時データで、再読み込みや退出で消え、他の人は参加できません。従来のCPU対戦にはFirebaseの設定や通信は不要です（AI利用時は外部APIへの通信が必要です）。
- 公開部屋「わいわい」「のんびり」「おえかき」はタイトルから名前だけで入れます。入口は固定で、GMが退出すると解散してデータは削除され、次の入室時に新しい部屋が作られます。通信断で空になった部屋も、5分経過後にその入口から訪れると掃除・再作成を試みます。サーバー常駐ではないため途中の通信断や同時入室による競合時は再入室が必要な場合があります。ゲーム終了画面からも新規参加できます。公開部屋は参加者全員にチャットや絵が見え、通報・モデレーションはありません。個人情報を投稿しないでください。
- **公開部屋の終了後の新規参加には、この変更の `database.rules.json` を Firebase Realtime Database に公開する必要があります。** 個室とオンラインの従来機能にも最新版のルールが必要です。Vercelへの画面デプロイだけではFirebaseのルールは更新されません。太い消しゴム（30を超える太さ）の同期にも最新版のルールが必要です。

- 描き手は正解者が出る前ならお題をパスできます。全員に「パス！」を表示した後、同じ描き手の新しいお題に変わり、絵は消えます。残り時間は引き継ぎます。正解後のパスはできません。
- ホストはGM操作からお題を終了して正解者に得点を付けるか、試合を強制終了して設定に戻せます。強制終了時は進行中のお題を破棄し、部屋・参加者・確定済みの得点を残します。次の試合を開始すると得点とチャット履歴はリセットされます。
- 部屋のチャットは最新100件を表示します。メッセージと描画の履歴は部屋ごとに保存され、参加者に共有されます。GMが「ホームへ」で退出すると部屋を解散し、対応するチャット・描画・お題・ヒント・正解記録を削除します。GM以外の退出では部屋は続きます。通報・モデレーション機能はありません。
- チャットの答え漏れを防ぐため、プレイ中の送信前に `chatGuard` の書き込みで新ルールを確認します。旧ルールのままでは回答や会話を送信できません。
- 接続状態と部屋の片付け、文字ヒント・制限時間・得点、「もどす」「全部消す」、チャットを利用するには、最新の `database.rules.json` を Firebase に公開し、新しい画面を Vercel にデプロイしてください。とくにパスと2回目の試合開始は旧ルールでは拒否されます。旧画面と新ルールは互換性がないため、公開の切り替え中や切り替え前から進行中の部屋では正常に遊べません。公開後は画面を更新し、新しい部屋を作ってください。
- お題は Realtime Database の `secrets` に保存し、描き手以外は結果発表まで直接読み取れないようルールで制限します。正解判定には本人のみ読める `verified` を使い、回答本文は正解枠に書き込みません。正解枠への追加と最後の枠による終了は同じトランザクションで行い、受付上限と期限を Firebase ルールで検証します。受付時刻は Firebase のサーバー時刻です。
- 制限時間ありの配点は経過時間を3分割し、初期値は早い順に回答者20／10／5点、描き手15／7／3点です。描き手は正解者ごとに加点されます。時間なしの初期値は回答者一律1点・描き手0点。各配点は設定で変更でき、終了時点で正解していない人に点は入りません。
- 文字ヒントはターンごとに事前に用意し、Firebase のサーバー時刻が指定の残り時間になった後だけ、そのターンの参加者に読み取りを許可します。時刻の同期や通信状況により、表示が少し遅れる場合があります。
- 画面右上でBGMと効果音をそれぞれON/OFFできます。タップなどの操作後に再生が始まり、タブが非表示の間はBGMを停止します。設定はこのブラウザに保存します。端末の消音設定やブラウザの自動再生制限によっては音が鳴らないことがあります。
- 専用のゲームサーバーを使わない友だち同士のカジュアルなゲーム向けです。ホストのブラウザがお題を生成しゲーム進行を管理するため、ホストは開発者ツールなどでお題や進行を操作でき、厳密な不正防止はできません。また、認証済みユーザーは合言葉を知っていれば部屋情報を読み取れます。公開サービスには追加の対策が必要です。8人制限は参加時の画面側の確認で、同時参加時には超過する可能性があります。ゲーム開始時は8人を超えると開始を拒否します。
- Firebase の onDisconnect でタブごとの接続状態を管理します。不在者の即時スキップには更新した `database.rules.json` の Firebase Realtime Database への公開が必要です。ホストが切断した場合、残っている参加者へホストが移ります。待機中の離席者は約30秒後に整理し、ゲーム中に出題者の全接続が切れて切断時刻が記録された場合は、そのターンを結果演出なしで自動スキップします。今後の不在者の描画順も飛ばします。接続中の参加者が1人になった場合は試合を終了します。切断前に確定した正解の得点は残ります。通信の一時的な切断でもスキップされることがあります。時間切れ・正解後はホストが次に進めます。プレイ中の参加者は同じブラウザの匿名認証が残っていれば、得点を引き継いで再参加できます。ブラウザのデータを消したり別の端末を使った場合は別人として扱われます。GMの通常退出では部屋を解散します（通信切断時は引き継ぎます）。
- 全員がブラウザを閉じる等で突然切断した場合、接続表示は Firebase が切断を検知した時点で外れますが、常駐サーバーがないため空き部屋の削除はその場では保証されません。最後の切断から5分以上経過し、その部屋を利用したブラウザが別の部屋を作成・参加した時に、部屋と関連データの削除を試みます。合言葉でその部屋に戻ろうとした場合は、戻る対象を自動掃除せず入室を試みます。利用履歴は各ブラウザ内に最大30件だけ保存します。誰も再訪しない部屋、ルール更新前にできた古い部屋、エラー時のデータは残ることがあるため、必要に応じ Firebase コンソールで確認・削除してください。旧ルールで作られた部屋は誤削除防止のため自動掃除しません。
- 以前の Cloud Functions 版や Firebase Hosting をすでにデプロイした場合、今回の変更では既存サービスは自動削除されません。必要に応じて Firebase コンソールで確認してください。

- カウントダウン・スタート・パス音: [MAKE10](https://github.com/Rikudo-ren/make10) が加工した [Kenney Audio Pack](https://kenney.nl/assets/audio-pack) の `click2` / `threeTone1` / `lowRandom`、CC0 1.0。終了のホイッスル音は Web Audio で生成しています。

- BGM: おえかきバトル用のオリジナル曲。`scripts/create-soft-bgm.py` で生成した、外部サンプルを使わないループ音源です。

- パス後もタイマーはリセットされず、パス演出中も残り時間が進みます。制限時間内に再開できない場合はそのまま時間切れになります。
- 今回の配点方式に対応するため、公開後は全員が画面を再読み込みして新しい試合を始めてください。古い画面と混在すると得点表示が一致しません。
- 通常のターン終了時は、ホイッスルと「終了！」を約3.2秒、答え発表を約2.6秒、得点・順位を約7秒表示してから「次へ」が操作できます。パスは従来どおり約2秒で次のお題に切り替わります。獲得点・合計のカウントアップ・順位変動を順番に表示し、演出はサーバーの終了時刻を基準にし、途中参加・再接続では現在の場面から表示します。最終ターン後はチャンピオン演出を表示します。動きを減らすOS設定にも対応しています。
- この演出に新たなFirebaseルールは不要ですが、古い画面と新しい画面では発表の長さが異なります。公開後は全員が画面を再読み込みしてください。
- 制限時間ありの場合、ゲーム画面の3色ゲージに各時間帯の回答者／描き手の配点を表示し、現在位置を示します。文字数と文字マスはキャンバスの上に表示し、ヒント公開時は通知と文字マスの強調でお知らせします。
